# 目标锚定执行 SOP（goal-anchored-sop）

## 三条铁律

1. **目标归人、目标冻结**：目标由人给出，执行方不得自己定义目标，也不得中途换成"我觉得更好"的目标。发现目标矛盾或做不到，发澄清卡问人，等人定了再继续。目标一旦确认，写进文件冻结；要改目标，先改文件、经人确认。
2. **禁止自评**：执行者不能评审自己的产出。握有全部上下文的一方负责执行，完成后交独立评审方（隔离上下文、自行取证）评审。独立性来自上下文隔离与立场分离，不来自"扮演另一个角色"。
3. **目标锚高于规划**：规划是手段，目标是终点。任务的价值在于它是否推进最终目标，不在于它是否在规划表上。任何时候，规划与目标冲突，以目标为准。

## 六步流程

### 第 1 步 · 提出目标

- 让人明确说出最终目标，原话保留，不改写、不脑补。
- 说不清就问清楚，不替人猜。目标含糊 = 后面所有步骤都失去准绳。
- 把目标写进文件冻结。这是全程唯一的尺子的来源。

### 第 2 步 · 围绕目标做设计规划

- 规划从目标反推，每一条规划都要能回答"这条是为了实现目标的哪一部分"。
- 回答不上来的规划项，删掉——它只是看起来该做，不服务目标。
- 规划要包含验收口径：每阶段"什么证据算达成"，先定好，不要做完再定。

### 第 3 步 · 按规划拆解任务

任务不是"规划要求我做所以我拆"，而是"为了达成最终目标所以需要做"。拆出的每个任务都要过两道检验：

- **目标检验**：这个任务直接推进最终目标吗？还是只是"规划里的一项"？只服务规划、不服务目标的任务，不拆。
- **必要性检验**：不做这个任务，目标能不能达成？能，就删；不能，才保留。

任务拆好后，按依赖关系排序，形成执行序列。每个任务前置写明：它服务目标的哪一部分、完成的验收证据是什么。

### 第 4 步 · 依次执行 + 独立评审（最多 3 轮）

- 按序列逐个执行任务，**做完一个再做一个**，不并行、不抢跑。
- 每个任务完成后，交独立评审方：隔离上下文、自己跑测试 / 读代码 / 查证据，对照该任务的验收口径评审。
- 评审提出问题 → 执行方修复 → 再评审。循环**最多 3 轮**。
- **3 轮后仍有卡点或问题**：停手，不硬修。请人介入，给出三样东西——① 卡在哪（具体）；② 为什么 3 轮没解决（原因）；③ 推荐意见（下一步怎么走的候选方案 + 优劣 + 明确推荐）。等人拍板再继续。

### 第 5 步 · 每项完成后做目标演进评估

- 每完成一个任务，先问：这个产出，是不是让最终目标向前演进了一步？
- 是 → 记录它推进了目标的哪一部分，继续下一个任务。
- 不是 → 说明这个产出完成了任务本身，但对最终目标没有贡献或贡献很小，问题出在哪。不默默略过。

### 第 6 步 · 问题分流

执行中冒出计划外的问题，按"是否阻塞最终目标"分三类处理，不在当前任务里就地修补计划外问题：

| 问题类型 | 判定 | 处置 |
|---|---|---|
| 非阻塞问题 | 不影响当前任务、也不阻塞最终目标 | 记入待办清单，留痕，不动当前规划路线 |
| 目标所需问题 | 为达成最终目标必须解决，但不属于当前任务 | 规划到合理的任务中，按正常流程排期执行 |
| 当前任务阻塞 | 不解决就无法完成当前任务，且当前任务服务目标 | 在当前任务内解决，有边界，不借机扩大范围 |

非阻塞的记待办，目标所需的进规划，只有真阻塞当前任务的才就地处理。不为修一个单点问题把任务带偏、把范围扩大。

## 完成宣布格式

不说"已完成"。只报——对照目标 X/Y 项达成，每项附证据；未达成项列出。尺子只有一把，重评只能对照已定口径挑错，要加标准先改文件、经人确认。
