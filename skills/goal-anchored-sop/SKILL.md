# 目标锚定执行 SOP（Goal-Anchored SOP）

**一句话准则：一切以实现最终目标为唯一准绳。期间任何步骤，如果它只是在完成"规划里的任务"而不是在逼近"最终目标"，就是偏离，必须纠正或叫停。**

这套 SOP 专治一种病：目标一开始定得很清楚，执行起来各种偏差，问题修完又有问题，换个评审者又冒出新点，任务越做越偏、无尽返工。根因不在模型能力，在过程丢掉了目标锚。适用于任何多步骤的项目或开发任务。

## 一、何时使用

- 推进一个项目 / 开发任务，尤其是多步骤、长链路的。
- 出现反复返工：修完又有问题、换人评审又出新点、同一问题反复修。
- 执行偏离了最初目标，或分不清"这个任务该不该做"。
- 需要独立评审执行产出，不能自评的场景。
- 用子 Agent / 多 Agent 协作执行任务。

## 二、三条铁律（贯穿全程，不可妥协）

1. **目标归人、目标冻结**：目标由人给出，执行方不得自己定义目标，也不得中途换成"我觉得更好"的目标。发现目标矛盾或做不到，发澄清卡问人，等人定了再继续。目标一旦确认，写进文件冻结；要改目标，先改文件、经人确认。
2. **禁止自评**：执行者不能评审自己的产出。握有全部上下文的一方负责执行，完成后交独立评审方（隔离上下文、自行取证）评审。独立性来自上下文隔离与立场分离，不来自"扮演另一个角色"。
3. **目标锚高于规划**：规划是手段，目标是终点。任务的价值在于它是否推进最终目标，不在于它是否在规划表上。任何时候，规划与目标冲突，以目标为准。

## 三、完整流程（六步闭环）

### 第 1 步 · 提出目标

- 让人明确说出最终目标，原话保留，不改写、不脑补。
- 说不清就问清楚，不替人猜。目标含糊 = 后面所有步骤都失去准绳。
- 把目标写进文件冻结。这是全程唯一的尺子的来源。

### 第 2 步 · 围绕目标做设计规划

- 规划从目标反推，每一条规划都要能回答"这条是为了实现目标的哪一部分"。
- 回答不上来的规划项，删掉——它只是看起来该做，不服务目标。
- 规划要包含验收口径：每阶段"什么证据算达成"，先定好，不要做完再定。

### 第 3 步 · 按规划拆解任务（关键：任务必须服务目标，不只是服务规划）

这是最容易出错的一步。铁律：**任务不是"规划要求我做所以我拆"，而是"为了达成最终目标所以需要做"。**

拆出的每个任务都要过两道检验：

- **目标检验**：这个任务直接推进最终目标吗？还是只是"规划里的一项"？只服务规划、不服务目标的任务，不拆。
- **必要性检验**：不做这个任务，目标能不能达成？能，就删；不能，才保留。

任务拆好后，按依赖关系排序，形成执行序列。每个任务前置写明：它服务目标的哪一部分、完成的验收证据是什么。

### 第 4 步 · 依次执行 + 独立评审（最多 3 轮）

- 按序列逐个执行任务，**做完一个再做一个**，不并行、不抢跑。
- 每个任务完成后，**禁止自己评自己**。交独立评审方：隔离上下文、自己跑测试 / 读代码 / 查证据，对照该任务的验收口径评审。
- 评审提出问题 → 执行方修复 → 再评审。循环**最多 3 轮**。
- **3 轮后仍有卡点或问题**：停手，不硬修。请人介入，给出三样东西——① 卡在哪（具体）；② 为什么 3 轮没解决（根因）；③ 推荐意见（下一步怎么走的候选方案 + 优劣 + 明确推荐）。等人拍板再继续。

### 第 5 步 · 每项完成后做"目标演进评估"

- 每完成一个任务，先别急着宣布完成。问一句：**这个产出，是不是让最终目标向前演进了一步？**
- 是 → 记录它推进了目标的哪一部分，继续下一个任务。
- 不是 → **必须明确告诉人**，不能默默略过、也不能假装它在服务目标。说明：这个产出完成了任务本身，但对最终目标没有贡献 / 贡献很小，问题出在哪。
- 这条是防"任务做了一堆、目标原地踏步"的关卡。

### 第 6 步 · 问题分流（防跑偏的核心机制）

执行中一定会冒出计划外的问题。按"是否阻塞最终目标"分三类处理，**绝不在当前任务里就地修补计划外问题**：

| 问题类型 | 判定 | 处置 |
|---|---|---|
| **非阻塞问题** | 不影响当前任务、也不阻塞最终目标 | 记入待办清单，留痕，**不动当前规划路线**。将来统一处理 |
| **目标所需问题** | 为达成最终目标必须解决，但不属于当前任务 | 规划到合理的任务中（新增任务或并入已有任务），按正常流程排期执行。**不在当前任务里直接修** |
| **当前任务阻塞** | 不解决就无法完成当前任务，且当前任务服务目标 | 在当前任务内解决，但要有边界，不借机扩大范围 |

一句话：**非阻塞的记待办，目标所需的进规划，只有真阻塞当前任务的才就地处理。** 任何情况下都不为修一个单点问题，把任务带偏、把范围扩大。

## 四、为什么必须这样：返工的三个根因

执行偏离目标、反复返工，根因有三个，这套 SOP 的每条规则都对应其中一个：

1. **验收的尺子每轮都不同**。每轮用当时自己定的标准宣布完成，下一轮换个更严的视角当然挑出新问题。不是问题反复，是**从没用同一把尺子验过**。→ 对应第 2 步的"验收口径先定"、第 4 步的"对照口径评审"。
2. **判据没落盘冻结**。目标和判据只活在对话里，会话一结束就蒸发，下一个执行者从零推断"什么算对"，必然有出入。→ 对应第 1 步的"目标写进文件冻结"。
3. **旧教训没变成回归检查**。修过的问题换个场景照样复现，因为只继承了方向，没继承反例。→ 对应第 4 步的"独立评审"和第 6 步的"问题分流留痕"。

**完成宣布的固定格式**（治根因 1）：禁止只说"已完成"。只允许报——"对照目标 X/Y 项达成，每项附证据；未达成项如实列出"。尺子只有一把，重评只能对照已定口径挑错，不许临时引入口径外的新标准（要加标准，先改文件、经人确认）。

## 五、反模式（明确禁止）

- 自己执行自己评审，或换个"人格"假装独立评审。
- 任务只是为了填满规划表，不检验是否服务最终目标。
- 目标还模糊就开工，边做边猜目标。
- 中途自己换目标，或把"我觉得更好"当目标。
- 报"已完成"但说不清对照哪条判据、证据是什么。
- 为修一个计划外的单点问题，把当前任务带偏、范围扩大。
- 非阻塞问题不记待办，当场就改，越改越偏。
- 3 轮评审还过不了，硬修不停手，也不请人介入。
- 每项完成后不做目标演进评估，任务一堆、原地踏步。

## 六、诚实边界

- 目标不清楚就问，不替人定目标。
- 产出对目标没贡献就直说，不粉饰。
- 评审 3 轮不过就停手上报，不假装收敛。
- 证据不足就说"无法验证"，不把"没发现问题"当"通过"。
