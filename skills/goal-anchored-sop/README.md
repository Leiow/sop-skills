# 目标锚定执行 SOP（goal-anchored-sop）

推进项目 / 开发任务时，防止执行偏离目标、反复返工的一套执行纪律。与领域无关，可用于任何多步骤任务。完整规则见 [SKILL.md](SKILL.md)。

## 解决什么问题

目标一开始很清楚，执行起来各种偏差：问题修完又有问题、换个评审者又冒出新点、任务越做越偏、无尽返工。根因不在能力，在过程丢掉了目标锚。本技能把"最终目标"重新钉成唯一准绳。

## 何时使用

- 推进项目 / 开发任务，尤其是多步骤、长链路的。
- 出现反复返工：修完又有问题、换人评审又出新点、同一问题反复修。
- 执行偏离了最初目标，或分不清"这个任务该不该做"。
- 需要独立评审执行产出，不能自评的场景。
- 用子 Agent / 多 Agent 协作执行任务。

## 六步闭环

1. **提出目标**：人说出最终目标，原话保留；说不清就问；写进文件冻结。
2. **围绕目标设计规划**：规划从目标反推，每条都要回答"实现目标的哪一部分"；同时先定验收口径。
3. **拆解任务**：每个任务过两道检验——**目标检验**（是否直接推进最终目标，而非只服务规划）与**必要性检验**（不做它目标是否还能达成）。只服务规划的任务不拆。
4. **执行 + 独立评审**：逐个执行，做完一个再做一个；禁止自评，交独立评审方对照验收口径评审；评审问题修复后再评，最多 3 轮；3 轮不过停手请人介入，给出卡点、根因、推荐意见。
5. **目标演进评估**：每项完成后问"产出是否让最终目标向前一步"；不是就说明它对目标没有贡献及问题在哪。
6. **问题分流**：非阻塞问题记待办、不动规划；目标所需问题归入合理任务、不在当前任务就地修；只有真阻塞当前任务的才就地处理。

## 三条铁律

1. **目标归人、冻结**：执行方不得自己定义或换目标；发现矛盾发澄清卡问人。
2. **禁止自评**：执行者与评审者分离，评审方隔离上下文、自行取证。独立性来自上下文隔离与立场分离，不是"扮演另一个角色"。
3. **目标锚高于规划**：任务的价值在是否推进目标，不在是否在规划表上；冲突时以目标为准。

## 返工的三个根因

这套 SOP 的每条规则都对应其中一个根因：

1. **验收的尺子每轮都不同**。每轮用当时自己定的标准宣布完成，换个视角当然挑出新问题。不是问题反复，是从没用同一把尺子验过。对应第 2 步"验收口径先定"、第 4 步"对照口径评审"。
2. **判据没落盘冻结**。目标和判据只活在对话里，会话一结束就蒸发，下一个执行者从零推断"什么算对"。对应第 1 步"目标写进文件冻结"。
3. **旧教训没变成回归检查**。修过的问题换个场景照样复现，因为只继承了方向，没继承反例。对应第 4 步"独立评审"和第 6 步"问题分流留痕"。

## 反模式

自己执行自己评审，或换个"人格"假装独立评审；任务只是为了填满规划表；目标还模糊就开工；中途自己换目标；报"已完成"但说不清对照哪条判据；为修一个计划外的单点问题把任务带偏、范围扩大；非阻塞问题当场就改；3 轮评审还过不了硬修不停手；每项完成后不做目标演进评估。
